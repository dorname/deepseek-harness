## Architecture

**一切皆插件(Cordis)**：runtime 是由 Cordis Loader 在启动时按层组合出的插件树。每个 package 是一个或多个 npm 包,通过 `ctx.effect()` / `ctx.on()` 贡献服务、事件、effects;卸载即撤销。

**Plugin Tree(自下而上)**:
1. 空 profile root
2. 每个 bundle 的 `cordis.patch.yml`(`@deepseek-ai/dsh-base` 是第一层,每个 profile 必有)
3. Profile 自身的 `cordis.patch.yml`
4. `$DSH_HOME/cordis.patch.yml`(machine-local)
5. `--patch <path>` argv overlays
6. Telemetry switch

**Capability Seam 三角色**:`Service Definition`(拥有 `ctx.<key>` 的 Cordis Service 类) + `Provider`(实现) + `Consumer`(模型可见工具)。三层齐全才构成完整 seam。

**Scope(作用域)** 是核心抽象:`dsh-scope` 提供 `ScopeKey` + `ScopedLayers` + `scopeTarget` 三件套。一个 live Agent 是它自己 scope 的 key;事件 dispatch 通过 `Scoped<Agent>` carrier 只投递给匹配 scope(含祖先)。每个 Agent 拥有独立的 tool registry 影子、prompt section、变量和 restrictions(基于 `tools.restrict` 的全局过滤 + scope-local 注册的合并)。

**Session Log 即真理**:`core/session` 的 `Session` 是 append-only event log。`deriveMessages()` 通过 surface(只包含 `user/message`、`assistant/message`、`tool/result`)派生 LLM 历史。"**Model-visible ⟺ logged**" 是核心不变量 — 任何到达 model 的输入必须可从 log 重放。

**三层事件域**:
- **Session events**(durable):`session/*`、`turn/*`、`step/*`、`user/message`、`assistant/*`、`tool/*` — 都走 `session/event`
- **Agent events**(live):`agent/pre-step`、`agent/request`、`agent/request-error`、`agent/turn-stopping` 等
- **Capability events**(policy):`fs/*`、`tools/*`、`telemetry/*`、`shell/*`

**Turn → Step 模型**:
```
turn/start
  claim inbox + assemble prompt + tools + variables
  agent/pre-step (waterfall, 可 reject / rewrite)
  step/start
    append user/message
    agent/request -> llm/stream -> assistant/chunk* -> assistant/message
    executeToolCalls (parallel 池 + exclusive barrier)
    tool/call -> tools/pre-execute -> tools/execute -> tools/post-execute -> tool/result
  step/end
  -> if 仍有 owed request 或 new next-step -> 下一步
  agent/turn-stopping (serial checkpoint)
turn/end
```

## Conventions

### Pre-release stance
- **Foundation over blast radius**:无外部消费者,优先正确基础而非兼容垫片;可自由重命名/重打包,后端拒绝旧磁盘格式
- SQLite 使用单调 `SCHEMA_VERSION`;`dsh-session` 保持 `SESSION_FORMAT_VERSION = 0`,无兼容性承诺

### Code style
- **ESM 一切**(`"type": "module"`),`.ts` 相对导入,包间走包名
- `strict: true` + `noImplicitAny` + `noUncheckedIndexedAccess` + `exactOptionalPropertyTypes`
- 注册皆 effects:`ctx.effect()` / `ctx.on()`,registry 的 `register()` 返回 disposer
- **关闭联合的 switch 终结于 `assertNever`**;merge-extensible 联合 fall-through 到 documented default
- **Waterfall listener 必须 `next()`** 委托;不调用即短路
- 空 `catch` 必须说明 swallow 内容和原因,`try` 只一条语句

### Naming & Structure
- 每个 npm 包 = `@deepseek-ai/dsh-<name>`,vendored 包 rescope 并 `private: true`
- `@deepseek-ai/cordis` 是 peerDependency(+ dev)
- 所有 `agent` 类的活插件是它自己 scope 的 key
- Opaque cross-boundary id 用 `Branded<B>`,不裸 `string`
- 信任 TypeScript 在 typed same-process 边界;runtime 校验只在 parser/config/queued/model-tool JSON/durable-file/worker/process/wire boundaries

### Persistence
- **JSONL(默认)**:`<root>/<normalized-cwd>/<encoded-id>/session.jsonl.zstd`
- **SQLite(opt-in, Schema17)**:同一进程单数据库;`data` ≥4 KiB 时 Zstandard level3 压缩(若更小则不压)

### Testing
- `test:coverage` 是 CI 覆盖率门([why](docs/testing.md))
- Keyless snapshot 通过真实可运行 example 录制
- 真实 API e2e 自跳过无 `DEEPSEEK_API_KEY`
- Both SDKs project the loop — 改动影响 Python 和 TS SDK 期望输出

### Docs
- 双语(中/英)Markdown,每个文件结尾一个换行
- 文档改动同步 JSDoc 契约 + README
- 机制性不变量走顶层 gate(`verify-*`),有受控豁免

### Process
- 单一仓库 + 多 PR stack,可 merge-forward / rebase
- `--force-with-lease`,禁止 `--force`
- Labels:一个 `kind/*`、多个 `area/*` + native Issue Type

### PR 模板要求
- **Agent Note**:非 trivial 变更必须在同 PR 包含 Agent Note(`notes/`);只 mechanical/local 改动豁免
- Archived notes 是 frozen 的,永不编辑
- 文件结尾恰好一个 newline;pre-commit 通过 `git diff --cached --check` 拦截
