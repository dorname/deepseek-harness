# core S37–S39（执行池域）— 测试用例

> 最后更新：2026-10-08
> 来源：变更 `agent-runner-pool`。场景来源 `core-01-requirements.md` §S37–S39；场景实现见 `core-S37-session-leases.md`、`core-S38-dispatch-continuation.md`、`core-S39-stream-relay.md`。

## 资源约束（验收执行，适用于本文件全部 ST 与对应 SMOKE）

- 契约/单元测试用 `@embedded-postgres/linux-x64` 免 root 真实 Postgres 二进制；二进制缺失时相关用例**显式 skip**并输出原因（可见、不假绿），其余用例照常执行。
- 嵌入式 Postgres 与多 runner/副本实例同时运行时按端口/数据目录隔离；ST 串行执行，不并行拉起多套共享库。
- 执行期间监控主机 CPU 利用率，峰值不超过部署配置阈值；超阈视为环境违规，先回收实例再继续，不得带违规定论。

## S37: 会话租约的跨节点单写者

### 1.1 单元/契约测试用例（来源：session-lease-postgres spec）

| ID | 描述 | 来源 | 前置条件 | 输入 | 预期输出 |
|----|------|------|---------|------|---------|
| UT-S37-01 | 获取-续约-释放全周期 | 租约后端 spec | 嵌入式 Postgres 运行 | acquire → 周期 renew → release → 再 acquire | 持有期间 ownerOf 恒为持有者；释放后立即可获取 |
| UT-S37-02 | 并发竞争恰一胜者 | 租约后端 spec | 租约空闲 | 两实例并发 acquire 同一会话 | 恰一成功；败者得占用失败并可见胜者标识 |
| UT-S37-03 | 过期接管恰一胜者 | 租约后端 spec | A 停止续约超过 ttl | 两实例并发 acquire | 恰一原子接管成功；败者占用失败 |
| UT-S37-04 | waitLost 丢失通知 | 租约后端 spec | A 持有且 waitLost 挂起 | B 接管（过期回写） | A 的 waitLost settle 且指明接管者 |
| UT-S37-05 | 二进制缺失显式 skip | spec 装配层 | Postgres 二进制不可用 | 触发装配 | 显式 skip 并输出原因，不产生假绿 |

### 2.1 场景测试用例

| ID | 描述 | 覆盖 Steps | 前置条件 | 操作序列 | 预期结果 |
|----|------|-----------|---------|---------|---------|
| ST-S37-01 | 双节点租约互斥（S37-AC-01/02） | 主路径+竞争 | 两实例连同一租约库 | A acquire → B acquire → A release → B acquire | B 首次占用失败；释放后 B 成功 |
| ST-S37-02 | 并发获取恰一执行者 | 竞争 | 两实例同时尝试 | 并发 acquire 同一会话 | 恰一持有；无窗口双持有 |

## S38: 队列派发与 inbox 投影接续

### 1.1 单元/契约测试用例（来源：agent-dispatch spec）

| ID | 描述 | 来源 | 前置条件 | 输入 | 预期输出 |
|----|------|------|---------|------|---------|
| UT-S38-01 | 入队去重与取走-重投 | 派发后端 spec | 嵌入式 Postgres 运行 | 同会话连续 publish 两次 → 取走 → 再 publish | 队列至多一行；取走后可再入队 |
| UT-S38-02 | 先租约后执行：竞争被排除 | Runner 编排 spec | 两编排循环指向同库 | 同会话派发被两循环取走 | 恰一取得租约执行；另一等待（不并发执行） |
| UT-S38-03 | 崩溃后接管接续（turn 边界） | Runner 编排 spec | runner A 持租约执行中 | 模拟 A 失联（停心跳）→ B 接管 resume | B 从共享层重放 + inbox 投影接续；事件序列无重复副作用 |
| UT-S38-04 | waitLost 即 cancel | Runner 编排 spec | A 执行中且 waitLost 挂起 | 注入接管 | cancel 被调用；租约释放；会话可重新入队 |
| UT-S38-05 | NOTIFY 丢失轮询兜底 | 派发后端 spec | 订阅端未收到通知 | 入队后仅轮询 | 派发项在轮询周期内被取走 |

### 2.1 场景测试用例

| ID | 描述 | 覆盖 Steps | 前置条件 | 操作序列 | 预期结果 |
|----|------|-----------|---------|---------|---------|
| ST-S38-01 | 派发接续（S38-AC-01） | 主路径 | 会话有历史与未消费输入 | publish → 空闲 runner 消费 | 取租约、resume、接续执行，事件落共享层 |
| ST-S38-02 | kill runner 后其他节点接续（S38-AC-02） | 异常流 | 两 runner 进程 | A 执行中被 kill → 等租约过期 | B 接管并继续 inbox 未消费输入 |
| ST-S38-03 | 双 runner 竞争排除（S38-AC-03） | 异常流 | 两 runner 同取派发 | 并发尝试执行 | 恰一执行（租约仲裁） |

## S39: 流中继的跨副本实时

### 1.1 单元/契约测试用例（来源：stream-relay-postgres spec）

| ID | 描述 | 来源 | 前置条件 | 输入 | 预期输出 |
|----|------|------|---------|------|---------|
| UT-S39-01 | 单调序号与双订阅同帧序 | 中继后端 spec | 嵌入式 Postgres 运行 | 连续 publish；两订阅者各自订阅 | 序号严格递增；两订阅者收到相同 (seq, payload) 序列 |
| UT-S39-02 | 游标追赶无缺口无重复 | 中继后端 spec | 已发布 N 条 | 以序号 k < N 为游标订阅 | 收到 k+1..N 全部记录，一次不重 |
